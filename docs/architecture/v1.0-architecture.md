# Flow Ring v1.0 Architecture Blueprint

> **设计目标**：覆盖 OS 的空间化交互层（Spatial Interaction Layer）
> **架构原则**：内核稳定、外壳可换、协议先行、单测覆盖
> **规模假设**：百万用户安装、5 万日活、千级并发 Profile 同步
> **MVP 平台**：Windows 10/11 x64（macOS 架构留接口，不实现）

> **⚠️ 硬约束补充**：本蓝图受 [addendum-v1.0.md](addendum-v1.0.md) 强制约束，包含 6 条核心禁止 / MVP 边界 / 测试要求 / 目录规范 / Agent 工作模式。有冲突以 addendum 为准。

### 1.2 关键架构决策

| 决策 | 选择 | 拒绝的方案 | 理由 |
|---|---|---|---|
| 桌面主进程 | .NET 8（WinForms 托盘） | WPF / Qt / Electron | 跨平台 .NET + WebView2 一致 |
| UI 渲染 | React + TypeScript + Vite | 原生控件 | 跨平台一致 + Studio 编辑器生态 |
| UI 宿主 | WebView2（Edge Embedded） | CefSharp / WebView | 系统自带 + 微软长期支持 |
| 进程通信 | WebMessage（低频） + Named Pipe（高频） | IPC Socket / 文件 | 低延迟 + 简单 |
| 持久化 | 分文件 JSON + 原子写 | SQLite / 单文件 JSON | 易同步 + 易版本控制 + 易恢复 |
| 进程模型 | 单进程多边界 | 多进程 | MVP 阶段足够，降低复杂度 |

## 2. Module Boundary Definition

### 2.1 分层架构（强制）

```
┌─────────────────────────────────────────┐
│  Layer 5:  Plugin Runtime (v1.1)        │  ← 第三方扩展
├─────────────────────────────────────────┤
│  Layer 4:  Application Layer            │  ← RingStudio / ProfileMgr / FlowCode
├─────────────────────────────────────────┤
│  Layer 3:  Domain Services              │  ← ContextEngine / ProfileResolver / FlowCodeCodec
├─────────────────────────────────────────┤
│  Layer 2:  Core Engine                  │  ← RingCore / ActionEngine / StateMachine
├─────────────────────────────────────────┤
│  Layer 1:  Platform Bridge              │  ← IDesktopBridge (Win32 实现)
└─────────────────────────────────────────┘
```

**依赖方向**：上层可以依赖下层，下层绝不允许依赖上层。

### 2.2 模块清单

| 模块 | 物理位置 | 语言 | 职责 | 依赖 |
|---|---|---|---|---|
| **RingCore** | `src/RingCore/` | C# / .NET 8 | Ring 图、方向计算、状态机、Action 调度 | 无 |
| **RingCore.Tests** | `tests/RingCore.Tests/` | C# / xUnit | RingCore 单元测试（>90% 覆盖） | RingCore |
| **DesktopBridge** | `src/DesktopBridge/` | C# / .NET 8 | `IDesktopBridge` + Win32 实现 | RingCore |
| **DesktopBridge.Tests** | `tests/DesktopBridge.Tests/` | C# | Bridge 集成测试（需要真实 Win32） | DesktopBridge |
| **DesktopHost** | `src/DesktopHost/` | C# / WinForms | 进程入口、托盘、WebView2 宿主、IPC | RingCore + DesktopBridge + RingProtocol |
| **RingProtocol** | `src/RingProtocol/` | C# + TypeScript | 双向协议定义（C# 端 + TS 端类型同步） | 无 |
| **RingUI** | `src/RingUI/` | TypeScript / React | 全部 UI 页面与组件 | RingProtocol (TS) |
| **RingUI.Tests** | `tests/RingUI.Tests/` | TypeScript / Vitest | 组件单测 + 状态机测试 | RingUI |
| **SharedSchema** | `src/SharedSchema/` | JSON Schema | Profile / Ring / Action / FlowCode 的 schema | 无 |

### 2.3 模块边界规则（强制）

1. **RingCore 不允许引用任何 OS API**（连 `System.Windows.Forms` 都不行）。
2. **DesktopBridge 不允许引用 UI 层**——它是纯桥接层。
3. **RingUI 不允许直接访问文件系统**——所有 IO 走 DesktopHost 通过协议暴露。
4. **RingProtocol 是 C# 与 TS 的唯一共享定义**——禁止在两侧手抄类型。
5. **每个模块有 `public API` 列表，超出列表的方法为 `internal`**——防止越层调用。

## 4. Core Interface Design

### 4.1 RingCore 核心接口

```csharp
// 方向枚举（8 向）
public enum Direction {
    Top, TopRight, Right, BottomRight,
    Bottom, BottomLeft, Left, TopLeft,
    Center  // Dead Zone
}

// 空间意图事件（InputAdapter 输出）
public readonly record struct SpatialIntentEvent(
    TriggerType TriggerType,
    PointF? OriginPoint,
    float Pressure,
    long TimestampMs,
    ModifierState Modifiers
);

// 方向判定
public interface IDirectionResolver {
    Direction Resolve(PointF center, PointF current, float deadZoneRadiusPx = 30f);
}

// Ring 节点（Graph Node）
public sealed class RingNode {
    public required string Id { get; init; }
    public required string ProfileId { get; init; }
    public Dictionary<Direction, RingSlot> Slots { get; init; } = new();
    public string? ParentRingId { get; init; }
}

public abstract class RingSlot {
    public required Direction Direction { get; init; }
}

public sealed class ActionSlot : RingSlot {
    public required string ActionRef { get; init; }   // 引用 ActionDef.Id
}

public sealed class ChildRingSlot : RingSlot {
    public required string ChildRingId { get; init; } // 引用 RingNode.Id
}
```

### 4.2 Action Engine 接口

```csharp
// 统一动作抽象
public interface IActionStep {
    string Id { get; }
    ActionContext Context { get; init; }   // 包含 Profile, currentApp, cursorInfo 等
    ValueTask<ExecutionResult> ExecuteAsync(CancellationToken ct);
}

public interface IActionExecutor {
    bool CanExecute(IActionStep step);
    ValueTask<ExecutionResult> ExecuteAsync(IActionStep step, CancellationToken ct);
}

// Action 定义（持久化形态）
public sealed record ActionDef(
    string Id,
    ActionKind Kind,                       // Keyboard / System / Application / AI / Workflow
    string DisplayName,
    string? IconHint,
    string? Hotkey,
    ActionPayload Payload,                 // 五种 Action 各自的负载
    IReadOnlyList<string> Tags
);

// 同步 / 异步 Action 区分
public enum ActionKind { Keyboard, System, Application, AI, Workflow }

public abstract record ActionPayload;
public sealed record KeyboardPayload(string Keys, KeyModifiers Modifiers) : ActionPayload;
public sealed record SystemPayload(SystemOp Op, JsonElement Args) : ActionPayload;
public sealed record ApplicationPayload(string ProcessName, string Command) : ActionPayload;
public sealed record AIPayload(string PromptTemplate, ModelRef Model) : ActionPayload;
public sealed record WorkflowPayload(IReadOnlyList<string> StepActionRefs) : ActionPayload;
```

### 4.3 DesktopBridge 接口（关键抽象）

```csharp
// 这是 OS 隔离层，所有平台特定实现都实现这个接口

// 上下文检测器
public interface IContextDetector {
    Task<ApplicationContext> DetectAsync(CancellationToken ct);

public sealed record ApplicationContext(

    nint WindowHandle,
```

### 4.5 Ring Protocol（C# ↔ TS 双向）

```
// 协议消息（节选）
C# → TS:
  RING_OPEN           { originPoint, ringTree, deadZonePx }
  RING_HIGHLIGHT      { direction }
  RING_CLOSE          { reason }
  PROFILE_LIST        { profiles[] }
  RING_STUDIO_LOAD    { profile, ringGraph, actionLibrary }

TS → C#:
  RING_DIRECTION_LOCK { direction }
  RING_TRIGGER        { triggerType, modifierState }
  ACTION_PREVIEW      { actionId }
  STUDIO_SAVE         { profile, ringGraph }
  FLOW_CODE_EXPORT    { profileId }
  FLOW_CODE_IMPORT    { code }
```

协议细节定义在 `src/RingProtocol/`，由 `SharedSchema` 自动生成 C# 和 TS 两端类型。

```json
      "oneOf": [

          "type": "object",
          "required": ["kind", "actionRef"],
          "properties": {
            "kind":      { "const": "action" },
            "actionRef": { "type": "string" }
```

## 6. Event Pipeline Specification

### 6.1 完整事件流（从按下到执行完成）

```
┌────────────────────────────────────────────────────────────────────┐
│ PHASE 1: RAW CAPTURE (Win32 层)                                    │
│   WH_MOUSE_LL Hook 拦截                                            │
│   时间预算: < 1ms                                                   │
└────────────────────────────────────────────────────────────────────┘
       │
       │ MouseHookProc(hwnd, msg, wParam, lParam)
       ▼
┌────────────────────────────────────────────────────────────────────┐
│ PHASE 2: INPUT NORMALIZATION (InputAdapter)                        │
│   MouseAdapter.RawToSpatialIntent()                                │
│   时间预算: < 1ms                                                   │
└────────────────────────────────────────────────────────────────────┘
       │ SpatialIntentEvent { triggerType=Mouse, originPoint, ts }
       ▼
┌────────────────────────────────────────────────────────────────────┐
│ PHASE 3: STATE MACHINE (InputStateMachine)                         │
│   Idle → Pressed → HoldDetected → RingOpening                      │
│   时间预算: 累计 < 150ms（用户感知阈值）                            │
└────────────────────────────────────────────────────────────────────┘
       │ HoldDetected 触发 RingOpenRequest
       ▼
┌────────────────────────────────────────────────────────────────────┐
│ PHASE 4: CONTEXT QUERY (ContextEngine + ProfileResolver)           │
│   GetForegroundWindow → PID → ProcessName                          │
│   ProfileResolver.Match(processName, windowTitle)                   │
│   时间预算: < 5ms                                                   │
└────────────────────────────────────────────────────────────────────┘
       │ ActiveProfile { id, rootRingId }
       ▼
┌────────────────────────────────────────────────────────────────────┐
│ PHASE 5: PROFILE LAZY LOAD (ProfileStore)                          │
│   缓存命中: < 1ms                                                   │
│   冷加载: < 50ms                                                   │
└────────────────────────────────────────────────────────────────────┘
       │ RingNode { id, slots[8], childRefs }
       ▼
┌────────────────────────────────────────────────────────────────────┐
│ PHASE 6: RENDER DISPATCH (Bridge → WebView2)                       │
│   BridgeServer.PostMessage(WebView2, RING_OPEN msg)                │
│   时间预算: < 50ms（WebView2 渲染首帧）                             │
└────────────────────────────────────────────────────────────────────┘
       │ React 渲染 Ring UI（Glass + Spatial）
       ▼
┌────────────────────────────────────────────────────────────────────┐
│ PHASE 7: SELECTION LOOP (60fps)                                    │
│   mousemove → Hook → Adapter → DirectionResolver                   │
│   时间预算: 每帧 < 16ms                                              │
└────────────────────────────────────────────────────────────────────┘
       │
       │ 用户移动鼠标
       │   - 距离 < 30px: DeadZone（不锁方向）
       │   - 距离 ≥ 30px: 计算最近方向 → 高亮
       │   - 方向变更时 BridgeServer.PostMessage(HIGHLIGHT)
       ▼
┌────────────────────────────────────────────────────────────────────┐
│ PHASE 8: RELEASE (用户松手)                                        │
│   Hook 拦截 mouse-up                                                │
│   状态机: Selecting → Executing                                     │
└────────────────────────────────────────────────────────────────────┘
       │ SelectedDirection + ActiveProfile
       ▼
┌────────────────────────────────────────────────────────────────────┐
│ PHASE 9: ACTION RESOLUTION (RingResolver)                          │
│   当前 Ring + Direction → ActionRef 或 ChildRingRef                 │
│   如果是 ChildRingRef: 状态机回到 Selecting（进入子 Ring）          │
│   如果是 ActionRef: 进入 Phase 10                                   │
└────────────────────────────────────────────────────────────────────┘
       │ ActionDef resolved
       ▼
┌────────────────────────────────────────────────────────────────────┐
│ PHASE 10: ACTION EXECUTION (ActionEngine)                          │
│   根据 Kind 选择 Executor                                           │
│   时间预算: < 30ms（同步 Action）                                   │
└────────────────────────────────────────────────────────────────────┘
       │ ExecutionResult { success, error?, durationMs }
       ▼
┌────────────────────────────────────────────────────────────────────┐
│ PHASE 11: CLOSE + LOG                                              │
│   BridgeServer.PostMessage(RING_CLOSE)                              │
│   LogStore.Append(ExecutionLog)                                     │
│   状态机: Executing → Closing → Idle                               │
└────────────────────────────────────────────────────────────────────┘
```

### 6.2 时序预算汇总

| 阶段 | 目标 | 硬上限 |
|---|---|---|
| Capture | < 1ms | 5ms |
| Normalize | < 1ms | 2ms |
| HoldDetected | 累计 150ms | 200ms |
| Context Query | < 5ms | 10ms |
| Profile Load（命中） | < 1ms | 3ms |
| Profile Load（冷） | < 50ms | 100ms |
| Render 首帧 | < 50ms | 100ms |
| Direction Update | 每帧 < 16ms | 20ms |
| Action Execute（同步） | < 30ms | 100ms |
| Action Execute（异步） | < 100ms 启动 | 5s |

### 6.3 错误处理与取消

| 错误源 | 处理策略 |
|---|---|
| Hook 丢失（OS 重启 / UAC 提示） | 自动重连 + 通知用户 |
| Context 查询失败 | 降级到 Default Profile |
| Profile 加载失败（JSON 损坏） | 加载最后快照 + 通知用户 |
| Action 执行失败 | 记录到 ExecutionLog + 提示用户 |
| WebView2 崩溃 | DesktopHost 重启 WebView2 + 状态保留 |
| 异步 Action 超时 | 取消 + 通知（未来版本流式 UI） |

## 8. Risk Analysis

### 8.1 技术风险

| 风险 | 影响 | 概率 | 缓解策略 |
|---|---|---|---|
| **反病毒软件误报** | 极高（用户安装失败） | 高 | EV 代码签名证书 + Microsoft SmartScreen 信誉积累 + 提交白名单 |
| **WH_MOUSE_LL 钩子丢失** | 高（核心功能失效） | 中 | 心跳检测 + 自动重连 + 备用触发键 |
| **WebView2 Runtime 缺失** | 高（旧系统） | 中 | 安装包内置 WebView2 Bootstrapper + 检测 + 自动装 |
| **Hook 性能抖动** | 中（卡顿） | 中 | 事件批处理 + 减少 GC（Struct 传递）+ 性能监控埋点 |
| **JSON Schema 演进** | 中（Flow Code 兼容性） | 高 | SemVer 严格管理 + 迁移脚本 + 旧 Profile 自动备份 |
| **WebView2 内存泄漏** | 中（长时间使用变卡） | 中 | 限制快照数 + 定期重启 WebView2 + 监控 RSS |
| **UAC 提权路径** | 中（某些 Action 需要） | 中 | 默认不提权，按需弹窗 + 任务计划程序开机启动 |

### 8.2 架构风险

| 风险 | 影响 | 概率 | 缓解策略 |
|---|---|---|---|
| **RingCore 与 OS API 耦合** | 高（跨平台失败） | 低 | 强制模块边界 + Code Review 检查 + 自动化依赖检查 |
| **协议两端类型漂移** | 中（运行时崩溃） | 中 | RingProtocol 单一来源生成 + CI 校验两端一致 |
| **Profile 损坏导致启动失败** | 高（用户无法使用） | 低 | 启动时校验 + 自动快照恢复 + 备份最近 3 个版本 |
| **Action 执行阻塞主线程** | 高（卡死） | 中 | 严格异步 + 取消令牌 + 超时熔断 + 心跳 |
| **WebMessage 反压** | 中（mousemove 丢帧） | 高 | mousemove 走 Named Pipe + 帧合并 + 客户端节流 |

### 8.3 产品风险

| 风险 | 影响 | 概率 | 缓解策略 |
|---|---|---|---|
| **用户学习成本高** | 高（留存低） | 高 | 内置 5 个高质量 Profile（默认 / 开发 / 设计 / 写作 / 办公）+ 引导视频 + Studio 一键重置 |
| **8 向认知负担** | 中（误触率高） | 高 | 默认 4 向 + 可切 8 向 + Dead Zone 默认 30px 可调 |
| **Profile 同步隐私** | 高（信任崩塌） | 中 | Flow Code 端到端加密 + 用户密码派生密钥 + 明确告知不上传 |
| **AI Action 期望管理** | 中（口碑崩坏） | 中 | v1.1 不发布前明确说"未集成 AI" + 不画饼 |

### 8.4 性能与扩展性风险

| 风险 | 影响 | 概率 | 缓解策略 |
|---|---|---|---|
| **1000 Profile 启动慢** | 中 | 低 | metadata 索引 + 按需加载 + 启动时进度条 |
| **巨型 Workflow Action** | 中（执行超时） | 中 | Workflow 分步执行 + 进度回调 + 取消 |
| **大量遥测数据** | 中（带宽/隐私） | 低 | 默认关闭 + 采样上报 + 本地优先处理 |

### 8.5 合规与安全风险

| 风险 | 影响 | 概率 | 缓解策略 |
|---|---|---|---|
| **GDPR / 数据驻留** | 高（欧盟下架） | 中 | 遥测默认关闭 + 数据本地化 + 提供数据导出/删除 |

| **第三方依赖漏洞** | 中（供应链攻击） | 中 | Dependabot + npm audit + dotnet list package --vulnerable + 周扫描 |
| **插件沙箱逃逸（v1.1）** | 高 | 中 | 进程隔离 + 权限白名单 + 强制签名 |

### 8.6 风险监控指标（持续追踪）
